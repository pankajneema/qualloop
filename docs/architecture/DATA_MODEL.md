## 0. Conventions (apply to every table unless stated)

### 0.1 Types

| Concept | Postgres type | Rule |
| --- | --- | --- |
| Primary key | `uuid` | UUIDv7, generated by the application (`uuid6.uuid7()`); SQL fallback `app_uuid_v7()` for SQL-side inserts (ADR-005) |
| Money | `bigint` | Paise. Column suffix `_paise`. Spec column `amount_inr` is stored as `amount_paise` (SPEC-GAP A-01) |
| Physical quantity | `bigint` | Integer units (SPEC-GAP A-72). `CHECK (> 0)` for rejected / received qty |
| Instant | `timestamptz` | Stored UTC. Never `timestamp without time zone` |
| Business date | `date` | Interpreted in the plant timezone (supplier-level: reference date, ADR-005 §4) |
| Enum | `text` + `CHECK (col IN (...))` | Lowercase snake_case values. Diagrams in the blueprint use UPPERCASE; same values |
| JSON | `jsonb` | `CHECK (jsonb_typeof(col) = 'object')` or `'array'` as stated; shape validated by Pydantic at the command |
| Hash | `text` | Lowercase hex SHA-256 (64 chars) for file/row hashes; `bytea` (32 bytes) for token hashes |
| Percent / score / PPM in snapshots | `numeric(p,s)` | Only in `supplier_scores_monthly` and `quality_targets` |
| IP | `inet` | |

### 0.2 Standard columns ("STD") — on all 48 tables

| Column | Type | Null | Default | Notes |
| --- | --- | --- | --- | --- |
| `id` | uuid | NOT NULL | app UUIDv7 | `PRIMARY KEY` |
| `tenant_id` | uuid | NOT NULL | — | `REFERENCES tenants(id) ON DELETE RESTRICT` (on `tenants`: `CHECK (tenant_id = id)`) |
| `created_at` | timestamptz | NOT NULL | `now()` | |
| `created_by` | uuid | NULL | — | `users.id` when the actor is an internal user; NULL for supplier session / system / AI actors (SPEC-GAP A-02). No FK (soft reference; actor of record is `activity_log`) |
| `updated_at` | timestamptz | NOT NULL | `now()` | Maintained by trigger `trg_set_updated_at` (BEFORE UPDATE) |
| `updated_by` | uuid | NULL | — | Same rule as `created_by` |

Plus on every table: `UNIQUE (tenant_id, id)` (target for composite FKs).
Append-only tables keep `updated_*` for uniformity; they always equal `created_*` (SPEC-GAP A-07).

### 0.3 Foreign keys

- All FKs between tenant tables are **composite**: `(tenant_id, x_id) REFERENCES x(tenant_id, id)`. A row can never
  reference another tenant's row, independently of RLS.
- Default `ON DELETE RESTRICT`, `ON UPDATE NO ACTION`. No `CASCADE` anywhere.
- The application role has **no DELETE privilege on any of the 48 tables** (§7.5: no hard deletes; masters archived).
  Only `idempotency_keys` grants DELETE (expiry cleanup).
- Every FK has a supporting index whose first column is `tenant_id`.
- Polymorphic references (`object_type` + `object_id`, `source_ref`, `source_object_*`, `scope_id`, `target_id`)
  have no FK; validated in the command; `object_type` constrained by `CHECK`.

### 0.4 Indexes

- Every index starts with `tenant_id`. Exceptions (cross-tenant system lookups, each used only through a
  `SECURITY DEFINER` function, ADR-004):

| Index | Why it is not tenant-first |
| --- | --- |
| `users_email_uq` on `lower(email)` | Login resolves the tenant from the email (A-03: email globally unique) |
| `magic_links_token_hash_uq` on `token_hash` | Supplier opens a link before any tenant context exists |
| `messages_provider_msg_uq` on `(channel, provider_message_id)` | Provider webhooks carry no tenant |
| `supplier_contacts_mobile_idx` on `(mobile)` (in addition to the tenant-first one) | WhatsApp STOP reply arrives with only a phone number (A-67) |
| `outbox_events_pending_idx` on `(created_at) WHERE processed_at IS NULL AND attempts < 5` | Dispatcher scans all tenants |
| `outbox_events_dead_idx` on `(created_at) WHERE processed_at IS NULL AND attempts >= 5` | Dead-letter alerting |

### 0.5 Row-level security (ADR-004) — agreed design, mirrored by `api/alembic/helpers.py`

Database roles:

| Role | Login | Attributes | Used by | Privileges |
| --- | --- | --- | --- | --- |

| --- | --- | --- | --- | --- |

| `app.supplier_id` | — | — | supplier of the scope object | same |

The single actor value for suppliers is **`supplier_session`**, in both the GUC and `activity_log.actor_type`.

Helper functions (baseline migration, `LANGUAGE sql STABLE`):
`app_current_tenant_id()`, `app_current_actor_type()`, `app_guc_uuid(name text)` (= `nullif(current_setting(name, true), '')::uuid`),
`app_is_supplier()` (= `app_current_actor_type() = 'supplier_session'`).

**Helper `enable_tenant_rls(table)`** (applied to all 48 tables; notation **T** below). Every table is deny-by-default for suppliers:

```sql
ALTER TABLE <t> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <t> FORCE ROW LEVEL SECURITY;
CREATE POLICY p_tenant ON <t> AS PERMISSIVE FOR ALL TO qualloop_app
  USING (tenant_id = app_current_tenant_id())
  WITH CHECK (tenant_id = app_current_tenant_id());
CREATE POLICY p_supplier_deny ON <t> AS RESTRICTIVE FOR ALL TO qualloop_app
  USING (app_current_actor_type() IS DISTINCT FROM 'supplier_session')
  WITH CHECK (app_current_actor_type() IS DISTINCT FROM 'supplier_session');
```

If the GUC is unset, `app_current_tenant_id()` returns NULL: no rows are visible and every insert is rejected (fail closed).

**Opt-in helper `enable_supplier_scoped_rls(table, select_predicate, insert=False, update_predicate=None)`** (notation **SS** below).
It drops `p_supplier_deny` and creates restrictive per-command policies. There is never a supplier DELETE.

```sql
CREATE POLICY p_supplier_select ON <t> AS RESTRICTIVE FOR SELECT TO qualloop_app
  USING (NOT app_is_supplier() OR (<select_predicate>));
CREATE POLICY p_supplier_insert ON <t> AS RESTRICTIVE FOR INSERT TO qualloop_app
  WITH CHECK (NOT app_is_supplier() OR <insert ? select_predicate : false>);
CREATE POLICY p_supplier_update ON <t> AS RESTRICTIVE FOR UPDATE TO qualloop_app
  USING (NOT app_is_supplier() OR <update_predicate or false>)
  WITH CHECK (NOT app_is_supplier() OR <update_predicate or false>);
CREATE POLICY p_supplier_delete ON <t> AS RESTRICTIVE FOR DELETE TO qualloop_app
  USING (NOT app_is_supplier());
```

`activity_log` and `outbox_events` use the predicate `false` for SELECT and allow INSERT. A supplier may append but never read.
For these two tables a supplier-actor `INSERT … RETURNING` would fail, so the writers never use `RETURNING`.

**Supplier-reachable tables (exhaustive). Every other table keeps `p_supplier_deny`.**
Abbreviations: `scope_t` = `current_setting('app.scope_object_type', true)`, `scope_id` = `app_guc_uuid('app.scope_object_id')`,
`LINKED_NCR(x)` = `x IN (SELECT ncr_id FROM ncr_scar_links WHERE scar_id = scope_id)` (evaluated under the caller's RLS).

The following tables are **denied** to suppliers despite being plausible candidates. `certificates` rows are created by the extraction worker (system actor), and supplier pages never read them. `plants` and `suppliers` are excluded (A-82). The same applies to every cost, money, risk, score, task, effectiveness and AI table.

All views are created `WITH (security_invoker = true)` so table policies apply to the caller (a view owned by `qualloop_owner` would otherwise see no rows under FORCE).

**CI tests**
- `test_every_rls_table_has_supplier_policy`: for every table, `pg_policies` contains `p_tenant` plus either `p_supplier_deny` or the four `p_supplier_*` policies.
- The set of tables with supplier policies equals the list above.

Grant shorthand used in the tables: **CRU** = SELECT, INSERT, UPDATE · **CR** = SELECT, INSERT (append-only,
plus trigger `trg_append_only` that raises on UPDATE/DELETE) · **CR+u(cols)** = append-only except the listed columns.

### 0.8 Validation CHECKs not stated in the spec (SPEC-GAP A-90)

The following CHECKs are format or positivity rules added for data quality. They are labelled `(A-90)` where they appear.
The human may keep or drop each one. Plants: `code ~ '^[A-Z0-9]{1,10}$'`. Users and contacts: `mobile` E.164. Suppliers: `gstin ~ '^[0-9A-Z]{15}$'`. Contact consents: the `source` value list. NCRs: `qty_checked NOT NULL AND > 0`. Receipts: `qty_received > 0`. Defect events: `qty_rejected > 0`. Every `amount_paise > 0`. Containment: `qty >= 0`. Every `length(btrim(...)) > 0` text check that the spec does not ask for. CHECKs that restate a spec enum, a spec formula or a spec "required" are not in this list.

### 0.9 Data-migration rule (D-7)

Schema DDL runs as `qualloop_owner`. A migration that reads or writes rows must follow these steps:
1. Run `SET LOCAL ROLE qualloop_app` for the data step, so RLS applies.
2. Iterate `app_active_tenant_ids()`, running one `set_config('app.tenant_id', <id>, true)` and one savepoint per tenant, with `app.actor_type = 'system'`.
3. Count the affected rows before and after for each tenant, and `RAISE` if the counts differ from the expected values. That aborts the whole migration.
4. Write one `activity_log` row per tenant with `action = 'migration.<revision>'`.

The rule is enforced by code review, plus the test `test_data_migrations_set_tenant_guc_and_assert_counts`, which runs on a two-tenant fixture.

## 10. Number sequences (§6 Numbering)

| Object | Format | Scope of `{seq}` | Month (`YYMM`) taken from | Padding |
| --- | --- | --- | --- | --- |
| NCR | `NCR-{plant.code}-{YYMM}-{seq}` | tenant + plant + YYMM | `capture_submitted_at` (or `created_at`) in plant timezone | min 3 digits (`SCAR-2611-014`, §15.4), grows past 999 |
| SCAR | `SCAR-{YYMM}-{seq}` | tenant + YYMM | `created_at` in the SCAR plant's timezone | min 3 digits |
| Debit note | `DN-{YYMM}-{seq}` | tenant + YYMM | `dn_date` | min 3 digits |

Allocation (no counter table): inside the creating transaction, `SELECT pg_advisory_xact_lock(hashtextextended(tenant_id || prefix, 0))`, then
`coalesce(max(split_part(<no>, '-', k)::int), 0) + 1` over rows `WHERE tenant_id = … AND <no> LIKE '<prefix>-%'` (index `(tenant_id, <no> text_pattern_ops)`), with `k = 4` for NCR (`NCR-{plant}-{YYMM}-{seq}`) and `k = 3` for SCAR/DN. The numeric max avoids text ordering errors past 999. The unique constraint is the backstop.
No gaps from rollbacks. Details and gap A-71.
